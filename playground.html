vue-write-behind

The write never comes back. Local state stays authoritative; the server's reply is discarded on purpose. Everything below runs against dist/vueWriteBehind.min.js.

1 — the cell does not jump

The server here is slow (2s) and opinionated: it always answers with the value UPPERCASED. Type, keep typing while the request is out, and watch the input: the reply never lands in it. This is the whole product.

discard('A1') drops the queued write. The request already on the wire cannot be recalled, so the key waits for it before anything else goes out — read the log: a PUT is always followed by its 200 before the next one.

{{ log.length ? log.join('\n') : 'no requests yet' }}

2 — failure never rolls back

Break the endpoint and keep typing. The key stays pending, the backoff grows 1 → 2 → 4 → 8s, and every attempt carries the current value — not the one that failed.

failed: {{ flakyOutbox.failed.length }} attempts: {{ flakyOutbox.failed[0]?.attempts ?? 0 }} pending: {{ flakyOutbox.pending.join(',') || 'none' }} 
{{ flakyLog.length ? flakyLog.join('\n') : 'no attempts yet' }}

3 — a batch endpoint

One call per tick carrying every due key. Resolve with { failed: [key] } to fail part of a batch — here C3 is always rejected by the server.

pending: {{ batchOutbox.pending.join(',') || 'none' }} failed: {{ batchOutbox.failed.map(f => f.key).join(',') || 'none' }}
